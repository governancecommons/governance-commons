# Governance Commons Ecosystem & Interoperability Commons

**Status:** Research / public documentation
**Authority:** Non-normative unless a document explicitly says otherwise
**Last verified:** 2026-09-30

## Purpose

Governance Commons is intended to function as a **commons**, not as an authority over the ecosystem.

The Commons exists to:

- collect relevant standards, protocols, research, organizations, and implementation work;
- make relationships among them easier to understand;
- preserve primary-source evidence and version context;
- distinguish documented fact from interpretation and proposal;
- identify overlap, complementarity, gaps, conflicts, limitations, and unresolved questions;
- teach the ecosystem to humans and make it easier for systems to navigate;
- surface warnings when a claim, metric, standard, implementation, or interoperability statement has important limitations; and
- contribute useful work back to existing communities where appropriate.

GC does not claim ownership, endorsement, certification, governance authority, or affiliation with external organizations merely because they are documented or linked here.

## Commons model

The public model is:

**Collect → Contextualize → Connect → Verify → Teach → Warn → Contribute**

The goal is information compaction without loss of provenance.

GC should prefer:

**source → evidence → context → interpretation → proposal**

over:

**claim → repetition → assumed authority**

## Relationship vocabulary

| Relationship | Meaning |
| --- | --- |
| REFERENCE | GC points users to relevant external work. |
| ALIGN | GC uses compatible terminology, concepts, or requirements. |
| INTEROPERATE | A concrete technical interoperability relationship exists or is being tested. |
| CROSSWALK | GC documents correspondence or differences between systems. |
| ADOPT | GC deliberately uses an external specification rather than recreating it. |
| CONTRIBUTE | GC has a candidate contribution for an external community. |
| RESEARCH | GC is investigating the relationship; no conclusion is implied. |
| WARN | GC documents a limitation, risk, ambiguity, conflict, or failure mode. |
| DISTINGUISH | GC documents an important semantic or scope difference. |

These labels describe GC's relationship to the work. They do not rate or rank the external project.

## Evidence discipline

Every ecosystem entry should preserve, where available:

- official project or organization name;
- official source URL;
- specification version or revision;
- publication or verification date;
- lifecycle/status;
- primary-source citation;
- scope;
- GC relationship;
- known overlap;
- known difference;
- proposed adoption or interoperability action;
- uncertainty or unresolved questions.

A current statement must not be inferred from an old version merely because the project name is unchanged.

## What this is not

The Commons is not:

- a claim that GC is the universal governance authority;
- a certification registry for external standards;
- a substitute for reading the primary specification;
- a ranking of standards or organizations;
- a statement of endorsement or affiliation;
- a guarantee that an implementation conforms merely because it appears in the ecosystem map.

## GC position

The central working thesis is:

> **Governance Commons provides common ground for discovering, connecting, comparing, verifying, teaching, and improving governance standards and practices. It does not need to own them.**

GC can be an umbrella in the sense of **common context and navigation**, while external organizations retain authority over their own standards, projects, specifications, and communities.

## Core semantic rule

> **No stage may silently impersonate the authority of another.**

A telemetry system can report an observation without deciding what it means.

An evaluation metric can measure a property without defining the universe it claims to represent.

An authorization system can issue a decision without becoming the sole source of historical evidence about what happened afterward.

A governance record can preserve evidence without acquiring the authority that generated the evidence.

A research summary can explain a source without becoming the source.

## Working evidence chain

**Observation → Evidence → Interpretation → Authority → Action**

These categories may interact, but they are not interchangeable.

The Commons should document the boundaries between them.

## Success condition

The Commons succeeds when useful knowledge becomes easier to find, understand, verify, compare, and apply — including when the correct outcome is to adopt, align with, contribute to, interoperate with, or retire GC work in favor of a better external solution.

That is the point of the Commons.
